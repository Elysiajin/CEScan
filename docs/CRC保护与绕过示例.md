# CRC 完整性保护与"过检测"示例

> 只用于本地学习与自研保护的测试，请勿用于破坏他人软件的合法性保护。

## 一、CRC 保护是什么

游戏保护（反作弊）常用**代码完整性校验**防止外挂直接改机器码：

1. 游戏启动时，对自己关键代码（如战斗结算函数）算一次 **CRC32**，存为基准值；
2. 一个保护线程每隔几十毫秒重新算一遍，与基准比对；
3. 不一致 = 代码被外挂改过 → 报警/踢下线/崩溃。

本工程的靶子 `bin/crc_target.exe`（源码 `tests/crc_target.cpp`）就是一个最小实现：

- `GameTick()` = "游戏主逻辑"，每 tick 回血 +10（外挂最想改成 +99）；
- `Watchdog` 线程每 100ms 对 `GameTick` 前 `0x40` 字节做位翻转法 CRC32；
- 与基准 `g_gold` 不符 → `[保护] CRC 校验失败！` → `ExitProcess(2)`。

## 二、怎么"自动寻找"CRC 检测点

`bin/crc_hunter.exe`（源码 `tools/crc_hunter.cpp`）演示了三层特征扫描：

| 特征 | 位置 | 说明 |
|---|---|---|
| 多项式立即数 `20 83 B8 ED`（`0xEDB88320` 小端） | 代码区 | 位翻转法 CRC 的铁证；`ror`/查表实现也绕不开这个常数 |
| 查表签名 `96 30 07 77 2C 61 0E EE`（表头 tab[1..2]） | 数据区 | 查表法 CRC 的铁证 |
| 检测点形状：**读基准值的指令 + 条件跳转** | 代码区 | 判别法：RIP 相对读取 `mov r32,[rip+d32]` / `cmp r32,[rip+d32]`，且读到的 4 字节 == 已知基准 GOLD → 其后 32 字节内第一个 `74/75/0F84/0F85` 就是"是否报警"的分支 |

关键技巧：GOLD 基准值可以让靶子打印出来（本例 `GOLD=...`），**用"读到的值 == GOLD"来验证候选指令确实在读基准**，避免误报；实际工作中也可以自己算 CRC 或扫内存找这个值。

另一个通用思路（本项目已具备）：用 **"谁访问了这个值"**（页守卫 + 谁读取）监视关键代码页——所有读它的指令里循环、高频的那个就是 CRC 校验线程。

## 三、怎么"过检测"

从"改动最小"到"最隐蔽"依次：

1. **改掉比对分支（本演示）**：检测点 jne → NOP（永不报警），或 je → jmp（永走通过分支）。定位自动、写法只有 2 字节。
2. **骗过比对结果**：钩住 CRC 函数让它永远返回基准值，或直接改内存里的基准 `g_gold`。
3. **让校验读到假数据**：页保护 + VEH，把保护线程对代码页的读重定向到一份"干净副本"（VMProtect/Themida 的思路反过来用）；或双映射同一物理页。
4. **别改代码**：只改数据/用调试器改寄存器/写外置内存，CRC 天然测不到。

本演示用第 1 种，并带**自验证**：打完补丁立刻真正改一次 `GameTick`（+10 → +99），靶子能活满 50 tick 打印 `GAME_OK`（退出码 0）才算成功；失败自动换下一个候选点重试。

## 四、怎么跑

```bash
cd CEScanVC
bash build_crc.sh          # 编译 bin/crc_target.exe + bin/crc_hunter.exe
./bin/crc_target.exe       # 单独看靶子：活满 50 tick，GAME_OK，退出码 0
```

## 五、防守视角（写保护的人该学什么）

- 别用"裸 CRC + 立即数多项式"：多项式可换 `0x82F63B78`(CRC32c) 等非常见值并运行时生成表；
- 校验代码自身也要被校验（互相校验、把基准藏在别处、多线程交叉校验）；
- 检测动作要异步/延迟（本例一改就死，真实保护会先记录再延迟封禁，让外挂无法用"改完马上验证"来试错定位检测点——本演示的"换候选重试"正是靠即时反馈）；
- 更进一步：VMP 化校验代码、把校验放进 VM 柱（这正是本工程《VM还原档案》/ HookRestore 处理的另一面）。
