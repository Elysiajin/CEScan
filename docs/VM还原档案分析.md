# 《VM还原档案》完整分析 × CEScanVC 自动还原实现对照

> 档案位置：`VM还原档案/1/1.txt`、`VM还原档案/2/2.txt`、`VM还原档案/3/1.txt`
> 结论先行：**是的，三份档案讲的就是 HOOK 还原 + 监视处理**。
> 「VM」的本质 = 壳把目标函数头 N 字节偷走（HOOK），跳进私有可执行区（023/02F 乱序柱）
> 执行完偷走的代码后再跳回。「还原」= 把被偷走的那 N 字节找回来。
> 「监视处理」= 用「谁访问/谁写入了这个值」找到 VM 柱内那条真正的读写指令，再对它做还原。

## 一、逐份拆解

### 1/1.txt —— 寄存器/堆栈差分法（手分析）

HOOK 头（00A5FED0，5 字节）：
```
E9 4A786501  jmp 020B771F        ← 被 HOOK
68 9B154901  push 0x149159B      ← 第一条未被偷的指令
```
做法：HOOK 头和第二行各下一个断点，对比两次中断的寄存器/堆栈。
ESP 从 0012E1CC 变 0012E1C4（差 8，说明 push 两个参数），EBP 指向第一个 push 后的 ESP ——
据此推断被偷的 5 字节是：
```
55      push ebp
8B EC   mov ebp, esp
6A FF   push -1
```

### 2/2.txt —— 三种方法

| 方法 | 思路 | 例 |
|---|---|---|
| 一 | 找同类函数对比头部（大量 CALL 头部都是 `55 8B EC 6A FF` 序言） | 004A89A0 的头部反推 97F660 |
| 二 | **搜跳回点**：HOOK 5 字节 + 2 字节 NOP = 7 字节，跳回点 = A+7；全进程搜 `jmp 009F6454`，跳回指令前面 7 字节就是还原码 | `009F644D = 64 89 0D 00 00 00 00` |
| 三 | **CALL 型 VM**：HOOK 是 `E8`（call），返回点 = 下一条指令地址；条件断点 `[ESP]==R` 自动跑到跳回处，再顺藤摸瓜找到真 handler | `0097F91D = E8 AE 89 C0 FF`（改写为 call 005882D0） |

### 3/1.txt —— 多级回溯（迭代补齐）

HOOK 5 字节（00A53D99）→ 搜 `jmp 00A53D9E`（跳回点）→ 找到 `02F500B4 jmp`。
但跳回指令前**凑不满 5 字节**：只能确认 3 字节 `8B 42 48`（mov eax,[edx+0x48]），
**还差 2 个**。于是：
1. 查找常量 `02F500A1`（一级 handler 的入口）→ 找到 `023DCB12 call 02F500A1`
2. 023DCB12 前面也凑不出 → **再次**查找常量 `023DCB12` → 找到 `02F53C80 call 023DCB12`
3. 02F53C80 往前正好 2 字节：`8B 16`（mov edx,[esi]）
4. 拼接：`8B 16` + `8B 42 48` = 完整还原 5 字节

## 二、CEScanVC 自动还原实现对照（src/HookRestore.cpp）

| 档案手法 | 引擎实现 | 自动化程度 |
|---|---|---|
| 判定是否 HOOK | `AnalyzeHook`：识别 E9/E8/EB/FF25/FF15/mov rax,imm64+jmp rax | 完全自动 |
| NOP 填充计算（档案 2 方法二，跳回点 = A+5+nop） | 逐字节数 `0x90`，跳回点含尾部填充 | 完全自动 |
| 搜跳回点 + 取前置字节（档案 2 方法二/三） | `ScanForResume`（一次全扫 128MB，VM 区优先）+ `PickBest` | 完全自动 |
| CALL 型 VM（档案 2 方法三，[ESP]==R） | 无需断点——`ScanForResume` 同样识别 `E8 call R`；无需运行时跟踪 | 完全自动 |
| FF25 间接跳转 | 解引用 `[rip+disp]` 指针槽取真正 VM 入口 | 完全自动 |
| **多级回溯**（档案 3） | `TryChain`/`ChainSolveTab`：一级凑不齐或混入 VM 垃圾时，从跳转表里查「谁引用了本 handler 入口」，逐级向上补齐，最多 3 级 | 完全自动 |
| VM 垃圾识别（档案 3 作者的人工取舍） | `IsVmJunky`：pushfd/pushad/lea rsp、`and al,imm` 类切割伪指令等特征 | 启发式自动 |
| 柱内命中反推 HOOK 入口（「谁写入了这个值」的实际场景） | `AnalyzeVMStub`：从命中点向前找跳出本区的 jmp，再回看 32 字节找 HOOK 入口 | 完全自动 |
| 寄存器/堆栈差分（档案 1） | 未实现——需要两次运行时断点；且多级回溯/垃圾识别已能覆盖其结论场景（函数头序言） | 不需要 |

### 求解优先级（PickBest 三级择优）

1. 前置 hookLen 字节且反汇编边界对齐、**不含 VM 垃圾** → 高置信
2. **多级回溯**：一级凑不齐就沿引用链往上追 → 高置信（档案 3）
3. 边界对齐但混有 VM 垃圾 / 边界不对齐 → 降级候选

### 关键工程点

- 全进程只扫一次建「跳转表」（目标地址 → 引用它的 jmp/call/push），多级回溯直接查表；
- 每级限 8 个命中点 × 8 个上游入口 + 全局 20000 节点探索预算，防止组合爆炸卡死；
- 回看窗口（找对齐起点）在 site 贴近分配页头时自动收缩，避免跨不可读页。
